## 4. TS-1 — GGUF quant formats (C1, C2, C3)

**Objective:** prove each of the 12 dequant functions is byte-correct against the authoritative
reference (llama.cpp), not just self-consistent, and that the loader reads the right bytes.

### TS-1.1 Differential testing vs llama.cpp — **P0**

The decisive test. Everything else in TS-1 is secondary to this.

**Setup**
```bash
git clone --depth 1 https://github.com/ggerganov/llama.cpp /tmp/llama.cpp
cd /tmp/llama.cpp && cmake -B build -DGGML_NATIVE=ON && cmake --build build -j
```

**Harness to write:** `tools/difftest_dequant.c` — links *only* ggml (not the full llama.cpp),
loops over every `ggml_type` we support, and for each:

| Step | Action |
|---|---|
| 1 | Generate a deterministic pseudo-random float32 tensor (fixed seed, N = 4096 elems) |
| 2 | Quantise with ggml's `ggml_quantize_chunk(type, ...)` |
| 3 | Dequantise with ggml's `dequantize_row_<type>()` → `ref[]` |
| 4 | Dequantise the *same bytes* with our `gguf_dequant_<type>()` → `ours[]` |
| 5 | Assert `max |ref[i] - ours[i]| == 0.0` (bit-exact; these are the same arithmetic) |

**Test matrix (18 types):** F32, F16, BF16, Q4_0, **Q4_1**, Q5_0, Q5_1, Q8_0, **Q8_1**, Q2_K,
Q3_K, Q4_K, Q5_K, Q6_K, **Q8_K**, **IQ2_XXS**, **IQ2_XS**, **IQ2_S**, **IQ3_XXS**, **IQ3_S**,
**IQ1_S**, **IQ1_M**, IQ4_NL, **IQ4_XS** (bold = new this session).

**Also differential-test at the tensor level** using real model files: for each downloaded GGUF,
dump every tensor via llama.cpp and via our loader, compare element-wise. Catches
`quant_bytes_for_elems`/offset bugs that a synthetic single-tensor test cannot.

**Exit criterion:** bit-exact match for all 24 types. Any mismatch is a P0 bug.

### TS-1.2 Block-size / geometry assertions — **P0**

Static-assert style checks mirroring ggml's own `static_assert`s, as a test:

| Type | Expected bytes/block | Elems/block | Regression guarded |
|---|---|---|---|
| Q4_1 | 20 | 32 | |
| **Q8_1** | **36** | 32 | **the 40→36 fix (C2)** |
| Q8_K | 292 | 256 | |
| IQ2_XXS | 66 | 256 | |
| IQ2_XS | 74 | 256 | |
| IQ2_S | 82 | 256 | |
| IQ3_XXS | 98 | 256 | |
| IQ3_S | 110 | 256 | |
| IQ1_S | **50** | 256 | plan doc said 26 — wrong |
| IQ1_M | **56** | 256 | plan doc said 37 — wrong |
| IQ4_XS | 136 | 256 | |

Assert `gguf_block_size(t) * (n/gguf_block_elems(t)) == quant_bytes_for_elems(t, n)` for all
types — the two tables must never disagree (they are maintained in different files).

### TS-1.3 Property-based / metamorphic tests — **P1**

| Property | Statement |
|---|---|
| **Scale invariance** | Dequantising a block whose `d` is doubled yields exactly 2× the output (for formats with a single multiplicative scale). |
| **Zero block** | An all-zero block with `d=0` dequantises to all zeros, no NaN/Inf. |
| **Determinism** | Same bytes → same floats, across repeated calls and across thread counts. |
| **Bounded output** | `|out[i]| <= |d| * max_codebook_value * max_scale` — no wild values. |
| **Partial-block contract** | `n_elems` not a multiple of block size → trailing elements are zero-filled, never OOB (already partly covered). |
| **Distribution match** | Dequantised mean/σ of a real tensor is within X% of the same tensor's Q8_0 (near-lossless) version. *(This is the check that flagged nothing wrong for C8 — keep it, but know its limits.)* |

### TS-1.4 Structure-aware fuzzing of the GGUF reader — **P1**

`gguf_reader.c` parses attacker-influenceable binary (any downloaded `.gguf`).

- **Harness:** `tests/fuzz_gguf_reader.c` with an `LLVMFuzzerTestOneInput` entry point
  (libFuzzer-compatible so AFL++ can reuse it unchanged).
- **Seed corpus:** truncated/real GGUF headers from the models in Appendix A.
- **Mutations to force:** absurd `n_tensors`/`n_kv`, tensor `offset` beyond the data region,
  dims that overflow when multiplied, unknown type IDs, string lengths ≥ file size, dimension
  count > 4, alignment values that aren't powers of two.
- **Run under:** ASan + UBSan; ≥ 1 M execs or 30 min, whichever first.
- **Pass:** no crash, no OOB, no unbounded allocation; every rejection is a clean error return.

### TS-1.5 Negative / boundary tests — **P1**

| Case | Expected |
|---|---|
| Tensor of an unsupported type ID (e.g. 99) | Clean `unsupported quant type` error, no crash |
| `n_elems` not a multiple of block size | Zero-filled tail, no OOB (ASan-clean) |
| Tensor whose `offset + size` exceeds the data region | Rejected at load |
| Zero-length tensor | Handled, no div-by-zero in `n/block_elems` |
| Nesting a type in an MoE expert-stride path | Correct per-expert stride (uses `quant_bytes_for_elems`) |

## 5. TS-2 — Grammar-constrained JSON decoding (C4, C5)

### TS-2.1 Differential fuzzing against a reference JSON parser — **P0**

The cheapest high-value test available for the PDA.

**Harness:** `tests/fuzz_grammar_json.py` (or C + a small JSON lib):

1. Generate random byte strings — three generators: (a) uniform random, (b) random tokens from
   the JSON alphabet `{}[]",:0-9a-z \t\n-+.eE\\`, (c) valid JSON mutated by 1–3 edits.
2. Feed each through `json_grammar_step()` char by char, then `json_grammar_finalize()`.
3. Compare our verdict with Python's `json.loads`:

| Our verdict | `json.loads` | Meaning |
|---|---|---|
| complete (DONE) | parses | ✅ agree |
| complete (DONE) | raises | ❌ **false accept — P0 bug** (we'd emit invalid JSON) |
| INVALID at char *i* | parses | ❌ **false reject — P0 bug** (we'd block valid output) |
| not DONE, never INVALID | raises | ✅ agree (valid prefix, incomplete) |

**Critical asymmetry to test explicitly:** a *prefix* that our PDA rejects must not be a prefix
of **any** valid JSON. Generate valid JSON, truncate at every offset, assert no INVALID.

**Target:** ≥ 100 k cases, zero disagreements.

### TS-2.2 Token-masking correctness — **P0**

| Case | Expectation |
|---|---|
| **No-deadlock invariant** | At every step of a real generation, at least one token is left unmasked. *(A fully-masked vocab is a hang — the single worst failure mode of constrained decoding.)* |
| EOS gating | EOS masked while grammar incomplete; unmasked exactly when `json_grammar_is_complete()` after trial-finalize |
| Multi-byte / byte-level BPE tokens | Tokens decoding to partial UTF-8 or raw bytes (`<0xHH>`) are simulated with the same bytes real generation emits |
| BOS-adjacent leading-space strip | Mask computed with the same `prev_token` the emitter uses |
| Mask is non-destructive | `fsm_compute_token_mask` never mutates `fsm->json` (scratch copy) — assert state equality before/after |
| Whole-vocab scale | Run against a real 49 152-token vocab, not just the 9-token synthetic fixture |

### TS-2.3 End-to-end JSON-mode validation — **P0**

For each model in Appendix A and each of `{CLI --json, API response_format}`:

```bash
# CLI
./adaptive_ai_engine --model <M> --prompt "<P>" --max-tokens 200 --temperature <T> --json
# API
curl -s -X POST localhost:8080/v1/chat/completions -d '{..., "response_format":{"type":"json_object"}}'
```

| Dimension | Values |
|---|---|
| Temperature | 0.0 (greedy), 0.7, 1.5 (high — most likely to expose grammar/sampler conflict) |
| top_p | 1.0, 0.9, 0.1 |
| max_tokens | 20 (forces truncation mid-JSON), 200, 2000 |
| Prompt | JSON-friendly; adversarial ("reply in plain English, no JSON"); prompt-injection ("ignore JSON and output ```markdown") |
| Streaming | `stream: true` and `false` |

**Assertions:** every completion parses with `json.loads` **or** is a legal truncated prefix
(when `max_tokens` cut it off); never a markdown fence; never trailing prose.
**Adversarial prompts are the key case** — grammar must win over instruction-following.

### TS-2.4 Regression: the non-JSON path must be untouched — **P0**

C5 changed a widely-used signature. Run the full existing suite plus golden-output checks with
`json_mode=false` and byte-compare against pre-change output at temperature 0, same seed.

### TS-2.5 Performance cost of masking — **P1**

`fsm_compute_token_mask` is O(vocab × token_len) **per generated token** — a full 49 k-token
decode+simulate loop each step. Measure tok/s with and without `--json` on the same model/seed.
Record the number; if the overhead is > ~20 %, file it as a known cost with a note that a
token-prefix trie / cached per-state masks is the standard optimisation.

### TS-2.6 Concurrency — **P1**

Two simultaneous API requests, one with `response_format=json_object` and one without: confirm
the 429-on-second-request serialisation still holds, and that no grammar state leaks between
requests (`FSMState` is stack-local per call — assert by interleaving and checking outputs).

## 6. TS-3 — Agent sandbox hardening (C6)

### TS-3.1 Adversarial argument corpus — **P0**

Table-driven; every row asserts `exec_policy_allows_args()` **and** `execute_command()` agree.

| Class | Payloads | Expected |
|---|---|---|
| Absolute path | `/etc/shadow`, `/etc/passwd`, `/proc/self/environ`, `/root/.ssh/id_rsa`, `//etc/passwd` | BLOCK |
| Home shortcut | `~/.ssh/id_rsa`, `~root/.bashrc` | BLOCK |
| Traversal | `../x`, `../../x`, `a/../../x`, `a/b/../../../etc/passwd`, `..`, `./../x` | BLOCK |
| Traversal look-alikes | `...`, `foo..bar.txt`, `.hidden`, `a..b/c` | ALLOW (must not over-block) |
| Encoded traversal | `%2e%2e%2f`, `..%2f`, `..\\`, `../` | **Investigate:** we do no decoding — `execvp` passes bytes literally, so these are literal filenames and safe. Test documents that reasoning. |
| Null/odd bytes | embedded `\0`, very long path (> PATH_MAX), UTF-8 homoglyphs | BLOCK or clean failure, never crash |
| Symlink escape | relative path that *is* a symlink to `/etc/passwd` | **Known gap** — see §6.2 |
| Flag injection | `ls --help`, `cat -v /etc/passwd`, `date -s 00:00`, `date --set=...`, `echo -e ...` | per policy: `date -s`/`--set` BLOCK; `cat -v` + absolute path BLOCK |
| Shell metacharacters | `ls; rm -rf /`, `ls && cat /etc/passwd`, `` ls `whoami` ``, `ls $(id)`, `ls \| nc` | ALLOW-as-literal-argument and **must not execute anything** — `fork`+`execvp` has no shell. Assert the metacharacters land as a literal (failed) filename, proving no shell exists. |
| argv[0] tricks | `./ls`, `/bin/ls`, `ls/../ls`, empty string, NULL | BLOCK (not in name allow-list) |

### TS-3.2 Known gaps to *document* via failing-by-design tests — **P1**

| Gap | Note |
|---|---|
| **Symlink escape** | A relative, non-`..` path can still point outside the CWD via a symlink. Correct fix is `realpath()` + prefix check against CWD. Current policy does not do this. **Recommend: add a test that documents current behaviour, and treat the `realpath` fix as a follow-up change.** |
| **TOCTOU** | Policy check and `execvp` are not atomic; a path could be swapped between them. Low severity given the human-approval gate, but real. |
| **PATH hijacking** | `execvp` searches `$PATH`; a malicious `ls` earlier in PATH wins. Fix = absolute-path table. |
| **`PROJECT_ZERO_AGENT_AUTO_APPROVE`** | Bypasses human review entirely. Test that the *policy* still applies in auto-approve mode (it does — it's inside `execute_command`). |

### TS-3.3 Resource-limit verification — **P1**

| Case | Expectation |
|---|---|
| `cat` on a FIFO / `/dev/zero` (relative path) | Parent timeout kills it; `timed_out=1` |
| CPU-burn child | `RLIMIT_CPU` fires (SIGXCPU) even if the parent loop stalls |
| Memory-hungry child | `RLIMIT_AS` (256 MiB) caps it; no host OOM |
| Output larger than `out_buf` | Truncated cleanly, NUL-terminated, no OOB (ASan) |
| `timeout_sec = 0` / negative | Defined behaviour, no infinite hang |

### TS-3.4 Interactive approval flow — **P2**

Reuse `tests/agent_pty_runner.py`: assert `y`/`Y` approves; `n`/empty/EOF/Ctrl-D denies;
`PROJECT_ZERO_AGENT_AUTO_APPROVE=1|y|t` auto-approves and anything else does not.

## 7. TS-4 — Open-bug RCA protocol (C8) — **P0**

The degenerate-output bug on IQ4_NL/IQ4_XS/Q3_K models. This is a *diagnostic* plan, not a
pass/fail suite; it is ordered so each step can terminate the investigation.

| Step | Experiment | If it shows… | Conclusion |
|---|---|---|---|
| **1** | Run the *same* `SmolLM2-135M-Instruct-IQ4_XS.gguf` through **llama.cpp** with the same prompt/seed/temperature | llama.cpp also degenerates | Not our bug — the quant is genuinely destructive for a 135 M model. **Close.** |
| | | llama.cpp is coherent | Our bug. Continue. |
| **2** | Differential test (TS-1.1) on that exact file, tensor by tensor | any mismatch | Dequant bug — fix and re-test |
| | | all match | Weights are right; the bug is downstream. Continue. |
| **3** | Dump layer-0 Q/K/V from both engines for the same input vector | values diverge | Matmul/dispatch bug for F32-heap weights |
| | | values match | Continue to attention |
| **4** | Dump post-softmax attention score distributions per layer | scores near-uniform (low variance/high entropy) | **Confirms the leading hypothesis** — attention collapse; investigate the attention scale (`1/sqrt(head_dim)`), RoPE, and GQA head mapping |
| **5** | Repeat on a **larger** IQ4_NL model (e.g. 1–3 B) | larger model fine | Small-model fragility, not a code bug |
| **6** | Compute perplexity + KL-divergence vs the F16 build of the same model (TS-5.2) | KL ≫ llama.cpp's KL for the same quant | Quantifies the damage and proves it's ours |

**Instrumentation needed:** a `TN_DEBUG_*` env-gated dump of attention scores per layer
(similar to the existing `--dump-tensors` CSV path and `g_tn_verbose` stats).

## 8. TS-5 — Cross-cutting testing

### TS-5.1 Golden-output regression suite — **P0**

Script `tests/golden_regression.sh`: for each (model, SIMD backend, thread count, classifier)
combination, run a fixed prompt at temperature 0 with a fixed seed and byte-compare against a
stored expected output.

| Prompt | Expected |
|---|---|
| "The capital of France is" | contains "Paris" |
| "2 + 2 =" | contains "4" |
| "<JSON prompt> --json" | parses as JSON |

Matrix: `--simd {scalar, avx2, avx512f, vnni}` × `--threads {1, 2, 4, 8}` ×
`--classifier {bf16, int8, int4}`. **Determinism requirement:** temperature 0 must produce
identical output across all backends/thread counts — any divergence is a real bug (the SIMD
backends must agree).

### TS-5.2 Model-quality testing (perplexity + KL-divergence) — **P1**

Standard methodology from the quantisation literature: WikiText-2 test set, perplexity vs an
F16 baseline, plus **per-token KL-divergence against the F16 reference** (a better isolation of
quantisation damage than perplexity alone). Build `tools/perplexity.c` (or extend the CLI with
`--perplexity <file>`).

| Metric | Use |
|---|---|
| Perplexity vs F16 | Headline quality number per quant type |
| KL-divergence vs F16 | Sensitive quant-damage signal; the C8 discriminator |
| Cross-check vs llama.cpp's own PPL for the same file | Our engine vs reference on identical weights |

**Caveat to record in results:** PPL and readability can diverge, and KLD's correlation with
downstream quality weakens near baseline — report both, don't gate on one.

### TS-5.3 Sanitizers and dynamic analysis — **P0/P1**

| Tool | Status | Action |
|---|---|---|
| ASan + UBSan | Running | Keep; ensure new tests are included (they are — auto-discovered) |
| **TSan** | **Missing** | **P0** — add `make test-tsan`; run thread-pool stress, parallel matmul, API concurrency. Highest-value missing sanitizer given the FM-001/FM-006 race history. |
| Valgrind/memcheck | Installed in CI, unused | P1 — run on the E2E path for uninitialised reads |
| MSan | Missing | P2 — requires a fully instrumented build; low ROI |
| **Heap profiling** | Missing | P2 — confirm the 28 GB-OOM class of bug (Q4_K dequant, 2026-07-30) can't recur with the new types |

### TS-5.4 Static analysis — **P1**

`clang-tidy` (bugprone-*, cert-*, clang-analyzer-*), `cppcheck --enable=all`, and
`scan-build make`. Focus on the new files. Expect findings on the existing codebase — triage
new-code findings only, to keep the signal clean.

### TS-5.5 Coverage — **P1**

`make coverage` via `gcov`/`llvm-cov`. **Targets:** ≥ 90 % line coverage on
`src/sampling/grammar_json.c`, `src/sampling/fsm.c`, `src/agent/cmd_exec.c`; ≥ 80 % on the new
dequant functions in `src/core/gguf_quant.c`. Report per-function so the untested IQ paths are
visible.

### TS-5.6 Performance regression gate — **P1**

Extend `tools/regression_bench.sh`: record tok/s for a fixed (model, threads, SIMD) baseline;

## 11. Risks and limitations

| Risk | Mitigation |
|---|---|
| **clang ASan unavailable locally** (broken apt dep) | Rely on CI for clang-sanitized runs; use gcc ASan locally; document in results |
| llama.cpp API drift breaks the diff harness | Pin a commit hash; record it in the harness header |
| Disk pressure from model downloads (~90–150 MB each) | Sequential download, delete between suites, `du -sh models/` guard |
| Tiny-model noise (135 M is inherently fragile) | Always corroborate C8 findings on a ≥ 1 B model before concluding |
| Fuzzing finds pre-existing unrelated bugs | Triage into a separate backlog; don't block Tier 1 merge on them |
| Perf tests noisy in a shared/VM environment | Best-of-N, sentinel runs, report ranges not point values (existing repo practice) |
| **Grammar deadlock** (all tokens masked → hang) | Explicit no-deadlock invariant test (TS-2.2) is mandatory, not optional |

## Appendix B — Command cookbook

```bash
# Full local gate (gcc)
make clean && make release CC=gcc && make test CC=gcc && make debug CC=gcc
# Cross-compiler
make clean && make release CC=clang && make test CC=clang     # ASan unavailable locally
# CMake parity (must build the 3 new sampling files)
cmake -B build-cmake -DENABLE_TESTS=ON && cmake --build build-cmake -j
# Single test binary
make build/tests/test_grammar_json CC=gcc && ./build/tests/test_grammar_json
# Golden output
./adaptive_ai_engine --model models/<M>.gguf --prompt "The capital of France is" \
  --max-tokens 16 --temperature 0 --threads 4
# JSON mode (CLI + API)
./adaptive_ai_engine --model models/<M>.gguf --prompt "<P>" --json --max-tokens 100
curl -s -X POST localhost:8080/v1/chat/completions -H 'Content-Type: application/json' \
  -d '{"model":"local","messages":[{"role":"user","content":"<P>"}],"response_format":{"type":"json_object"}}'
# Tensor dump for differential work
./adaptive_ai_engine --model models/<M>.gguf --prompt "x" --max-tokens 1 --dump-tensors /tmp/d.csv
```

### Known testing gotchas (learned 2026-09-17 — read before writing tests)

1. **The engine auto-applies the model's GGUF chat template to every prompt.** Manually adding
   `<|im_start|>` tags double-wraps. Check `--verbose`'s `[DBG] formatted prompt:` line.
2. **The CLI banner/config prints to stdout**, so `--json | jq` needs the banner skipped. The
   API path has no such issue.
3. `tokenizer_decode()` returns a **thread-local static buffer** — reused on every call. Never
   hold two decoded pointers at once.
4. Test scales that aren't exact in fp16 (e.g. 0.1) will fail hand-computed assertions — use
   powers of two (0.125, 0.25, 0.5).
5. `make` does **not** rebuild when only `CC` changes — `make clean` between compilers or you're
   testing stale objects.
